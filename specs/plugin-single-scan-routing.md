# Plugin single-scan publication routing

Code-plugin and bundle-plugin publication owns one artifact-bound ClawScan adjudication during prepublication. Its complete bounded `llmAnalysis` and A.I.G evidence are retained on the immutable release and shown by detail/audit readers. A clean check without completed matching evidence is not publishable. An explicit rescan uses the same evidence validation; A.I.G is supporting evidence rather than an independent publication verdict. Standalone skill routing is unchanged.

Automatic plugin `publish`, `backfill`, and legacy update/repair enqueue sources produce `securityScanJobs.scanMode = "endor-report-only"`. These jobs may store only an Endor report. They cannot replace ClawScan, A.I.G, SkillSpector, verification, moderation, release identity, files, or tags. Endor findings alone cannot change the publication verdict. Missing/failed Endor does not mean clean. The worker must branch on this mode before invoking any ClawScan pipeline and complete with only `endorAnalysis` (no synthesized `llmAnalysis`). Existing Endor enablement remains authoritative; this routing does not enable Endor.

Legacy automatic plugin ClawScan jobs without this mode remain stored, but cannot be claimed, completed, or revived by failed/expired lease recovery. This code does not delete or migrate historical jobs, reports, versions, or artifact bytes. Explicit `manual` and admin `bulk-rescan` jobs retain ClawScan authority and remain separate from automatic report jobs, including enqueue deduplication and dry-run counts. Existing authorization boundaries are retained.

Automatic plugin backfill now selects missing/failed Endor reports, never a missing/error ClawScan result. Plugins without a usable historical adjudication need an explicit reviewed rescan, not silent automatic re-adjudication. Template packages retain their prior automatic routing. No production pin, environment, deployment, or data change is part of this implementation.
